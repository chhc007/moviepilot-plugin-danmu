# 实施规格：Danmu v1.12.1 修复滚动弹幕速度算法

> 仓库：`~/workspace/projects/moviepilot/danmu/`
> 基线：v1.12.0
> 目标版本：**v1.12.1**
> 用户反馈：弹幕移动不流畅（此前用户误以为是性能问题，实为算法 bug）

## 一、缺陷（代码实测）

`danmu_generator.py` 的 `convert_comments_to_ass()` 里，**同一个函数内用了两套不一致的文本宽度**：

```python
gap = 1
text_width = len(text) * fontsize * 0.6                       # 1408行：含 0.6 系数
velocity = (width + text_width) / duration                     # 1409行：用它算速度
leave_time = text_width / velocity + gap                       # 1410行：用它算离场时间
...
styles = f'\\move({width}, {initial_y}, {-len(text)*fontsize}, {initial_y})'  # 1418行：漏了 0.6 ❌
```

**移动终点 `-len(text)*fontsize` 漏了 0.6 系数** → 终点比实际文本宽度远 **1.67 倍**。

### 实测影响（width=1920, fontsize=54, duration=15）

| 文本长度 | 移动距离 | 实际速度 |
|---|---|---|
| 11 字 | 2514 px | 168 px/s |
| 23 字 | 3162 px | **211 px/s** |

**两个后果**：
1. **速度偏慢**（168~211 px/s，B站/弹弹play 标准约 200-300 px/s）
2. **长短弹幕速度不一致**（越长越快）→ 观感"忽快忽慢"，即用户说的"不流畅"

## 二、修复

**终点改用 `text_width`**，让「移动距离 / 速度 / 离场时间」三者一致：

```python
gap = 1
text_width = len(text) * fontsize * 0.6
velocity = (width + text_width) / duration
leave_time = text_width / velocity + gap
...
# 修复：终点 = 负的文本宽度（与 velocity 计算一致），所有弹幕同速
end_x = -text_width
styles = f'\\move({width}, {initial_y}, {end_x}, {initial_y})'
```

**效果**：
- 所有滚动弹幕**速度统一** = `(width + text_width) / duration`
- 终点正确（文本完全滑出屏幕左侧后消失），不浪费行程
- duration=15 时速度约 128 px/s（距离变短了）→ **若要更快，调 duration 即可**（如 duration=10 → 约 192 px/s）

## 三、附带改进（可选，建议做）

**速度可配置**：当前 duration 是唯一速度旋钮，但语义不直观（"存活秒数"）。
可选：加 `danmu_speed` 配置（px/s），内部换算 duration = (width + text_width) / speed。
→ **先不做**，避免范围扩大；本次只修算法一致性。

## 三、附带新增：同屏弹幕上限配置（用户要求）

### 背景（实测）
樱花庄 E01：**平均同屏 43.3 条，峰值 54 条**（15 秒窗口）→ 飞牛TV 渲染不掉帧才怪。这是卡顿**主因**。

注意：`screen_area: quarter` **只减少轨道数，不减少同屏总量** —— 反而让 43 条挤在 1/4 区域，更密。

### 新增配置项 `max_same_screen`

| 项 | 值 |
|---|---|
| key | `max_same_screen` |
| 默认 | `0`（0 = 不限制，保持向后兼容） |
| 范围 | 0 或正整数（建议 10~30） |
| 含义 | 同一时刻**最多保留多少条弹幕**，超出的丢弃 |

**实现**（`convert_comments_to_ass` 内）：
- 维护一个"当前活跃弹幕"列表（按 start/end 时间）
- 处理每条弹幕前，先剔除已结束的
- 若活跃数 ≥ `max_same_screen`（且 >0），**丢弃该条**（计入 `dropped_overflow`）
- 日志汇总：`N 条弹幕因同屏上限被丢弃`

**注意**：
- 与现有 `dropped_full`（轨道全满丢弃）区分，分别统计
- 只影响新生成的 `.ass`（旧文件不变）
- 优先级：滚动弹幕（pos=1）按时间顺序保留；若要对顶部/底部（pos 4/5）豁免，可考虑——**先统一处理，简单可靠**

### 三层同步（照 `screen_area` 模式）
1. `__init__.py`：`self._max_same_screen = config.get("max_same_screen", 0)`
2. `danmu_generator.py`：`convert_comments_to_ass` 加参数 `max_same_screen: int = 0`
3. 前端 `src/components/Config.vue`：`defaultConfig` + normalize + 模板加输入框（数字，hint 说明 0=不限）
